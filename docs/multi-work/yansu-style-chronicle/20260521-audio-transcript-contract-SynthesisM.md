# Yansu-Style Chronicle Audio Transcript Contract Synthesis

## Scope

This slice adds a first-class Chronicle-owned audio transcript evidence contract. It does not implement real audio capture, Silero VAD inference, SenseVoice ASR inference, or speaker embedding inference.

The behavioral goal is that a transcript produced by a future local runtime, fixture importer, or external transcription path can be ingested into Cradle Chronicle, stored as durable evidence, shown in Settings, mixed into the activity timeline, and searched through the existing memory index.

### Server

Files touched:

- `apps/server/src/modules/chronicle/model.ts`
- `apps/server/src/modules/chronicle/index.ts`
- `apps/server/src/modules/chronicle/service.ts`
- `apps/server/src/modules/chronicle/README.md`
- `apps/server/tests/chronicle.test.ts`

New routes:

- `GET /chronicle/audio-transcripts`
- `POST /chronicle/audio-transcripts`

`recordAudioTranscript()` behavior:

1. Rejects invalid transcript timestamps and reversed transcript or segment ranges with 400 responses.
2. Upserts `chronicle_audio_transcripts` by `sourceId`.
3. Rebuilds ordered `chronicle_audio_segments`.
4. Calls `recordMemory()` to derive an imported memory with `sourceId = audio-transcript:<sourceId>`.
5. Backfills `chronicle_audio_transcripts.memoryId`.
6. Records a `chronicle_events` row with `type = audio`.

The ordering is intentional: raw transcript evidence is persisted before the derived searchable memory is attached.

Server status now exposes:

- `totalAudioTranscripts`
- `lastAudioTranscriptAt`

Timeline now includes `sourceType = audio` entries with transcript preview text.

- `ChronicleAudioTranscriptReport`
- `ChronicleAudioTranscriptSegmentReport`
- `ChronicleAudioTranscriptSource`

## Validation

Passed:

```bash
pnpm exec drizzle-kit generate --config drizzle.config.ts
pnpm --filter @cradle/server exec tsc --noEmit
pnpm --filter @cradle/server exec vitest run tests/chronicle.test.ts
pnpm --filter @cradle/web exec eslint src/features/chronicle/use-chronicle.ts src/features/chronicle/chronicle-settings.tsx
cargo fmt --manifest-path chronicle/Cargo.toml
cargo test --manifest-path chronicle/Cargo.toml
cargo clippy --manifest-path chronicle/Cargo.toml --all-targets -- -D warnings
```

The server test proves:

- `POST /chronicle/audio-transcripts` returns a transcript entry.
- Transcript and segment rows are persisted.
- malformed timestamps and reversed ranges return 400.
- repeated ingest for the same `sourceId` rebuilds segments and the derived memory rather than keeping stale transcript text.
- The transcript row is linked to a derived memory.
- Memory search finds transcript text.
- Timeline includes an `audio` entry.
- Status reports transcript count and latest transcript timestamp.

The Rust test proves:

- transcript report JSON uses the Server camelCase contract;
- source/status variants serialize to the Server enum values;
- confidence cannot be constructed outside `[0, 1]`;
- local validation rejects reversed segment ranges;
- segment fields serialize correctly;
- metadata can explicitly state that VAD/ASR/speaker runtime is not implemented.

## Known Limitations

This slice intentionally does not implement:

- microphone capture;
- system audio capture;
- audio permission flow;
- Silero VAD loading or inference;
- SenseVoice/Sherpa ASR loading or inference;
- speaker embedding extraction or matching;
- transcript artifact writer in Rust daemon;
- transcript retention policy beyond DB rows and caller-provided artifact paths.

The remaining runtime work should consume this contract rather than replace it.
