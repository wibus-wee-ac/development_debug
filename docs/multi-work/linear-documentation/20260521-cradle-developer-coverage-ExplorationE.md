# Cradle Developer Documentation Coverage Handoff

## Scope

本 handoff 是开发者文档覆盖审计，不实现正式文档页。审计目标来自 `docs/exec-plans/20260521-05-linear-style-documentation.md`，证据范围限定在：

- `apps/server/src/modules/**`
- `apps/server/src/http/**`
- `apps/server/src/plugins/**`
- `apps/server/src/openapi/**`
- `packages/cli/**`
- `src/cli/**`
- `packages/plugin-sdk/**`
- `packages/db/**`
- `plugins/**`
- `apps/server/package.json`
- `documentations/package.json`

核心约束是仓库 namespace ownership 原则：文档必须说明每个能力的 owner，允许读取其他 namespace 的数据，但不能把写入语义放到非 owner namespace。例如 `skills` 可以读取标准 `.agents/skills` 兼容目录，但 Cradle-owned writes 应落在 `~/.cradle/skills`、workspace `.cradle/skills` 或 agent-scoped `~/.cradle/agents/{agentId}/skills`。

## Evidence Summary

- Server app composition: `apps/server/src/app.ts` imports and mounts all explicit Elysia modules, applies CORS/request-id/request-logger/error/OpenAPI plugins, starts Chronicle background work, registers PTY routes, mounts `testReset` only in `NODE_ENV === 'test'`, then activates server plugins.
- HTTP/OpenAPI: `apps/server/src/http/openapi.ts` exposes `/docs`, `/openapi.json`, and `/docs/openapi.json`; `apps/server/src/http/README.md` documents request id, error mapping, validation, actor context, and OpenAPI setup.
- CLI generation: `packages/cli/scripts/generate-cli.ts` loads the live server OpenAPI document, extracts operations with `x-cradle-cli`, writes `packages/cli/src/commands/generated/**`, and updates `resources/skills/cradle-cli/SKILL.md`.
- CLI runtime: `packages/cli/src/runtime/**` handles Commander registration, `--server`, `CRADLE_SERVER_URL`, `CRADLE_CHAT_SESSION_ID`, JSON/pretty/table/NDJSON output, and strict flag parsing.
- Plugin SDK: `packages/plugin-sdk/DEVELOPERS.md` and `packages/plugin-sdk/src/{index,server,web,desktop}.ts` define manifest metadata, server/web/desktop contexts, MCP/skill/hooks/events/storage APIs, route segment derivation, and capability identity derivation.
- Plugin host: `apps/server/src/plugins/**` discovers plugin packages, creates host-owned descriptors, activates server entries under `/api/plugins/{routeSegment}`, serves `/api/plugins` and `/api/plugins/:name/web.mjs`, projects MCP/skill/hook capabilities, and tracks layer lifecycle.
- Database ownership: `packages/db/src/schema/**` splits Drizzle schema by owner contexts: shared workspace, identity, chat, backend control plane, runtime, ACP, issue, Kanban board views, issue-agent, observability, session-await, Chronicle, and automation.
- Testing workflow: `apps/server/tests/README.md`, `apps/server/package.json`, `packages/cli/src/runtime/*.test.ts`, `packages/db/src/message-snapshot-migration.test.ts`, and plugin tests under `plugins/browser-use/src/*.test.ts` show Vitest coverage and available scripts.

## Ownership Notes For Final Docs

- `Issue` owns issue semantics even though historical table names still begin with `kanban_*`; `Kanban` owns board/view configuration only.
- `Session` owns CRUD and persisted conversation resources; `Chat Runtime` owns turn execution, streaming, cancellation, and provider orchestration.
- `Agent Identity` owns user-visible author/persona semantics; provider profiles are runtime configuration and must not be described as authors.
- `Skills` may read standard `.agents/skills` for compatibility, but Cradle writes should remain under Cradle-owned paths.
- `Plugin Host` owns descriptors, route segments, layer state, and capability records; plugins own their local capabilities through owner-prefixed capability IDs.
- `Automation` owns durable definition/run/artifact records; execution of chat turns remains owned by `chat-runtime`.
- `Chronicle` Server owns Cradle DB/API state and summary orchestration; the Rust daemon owns local capture and artifact production.
- `Provider` and `Profile` docs should not imply that external provider registries own Cradle DB lifecycle; Cradle stores only its runtime/profile/cache/audit projections.
