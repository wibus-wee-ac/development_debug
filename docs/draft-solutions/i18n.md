# i18n Architecture SPEC

本文是一份可复用到全新前端项目的 i18n 架构规格。目标栈是 Next.js App Router、TypeScript、React、i18next、react-i18next。若项目不是 Next.js，仍可复用资源模型、key 约定、校验工作流和 CI gate；仅需替换请求层与 HTML 挂载层。

## 1. 目标

本架构要解决四类问题：

1. 运行时一致性：服务端、客户端、URL 参数、cookie、HTML `lang`/`dir`、React 渲染语言必须收敛到同一个 locale。
2. 资源可维护性：默认文案有唯一 source of truth，多语言 JSON 可由脚本校验，不依赖人工记忆。
3. 类型与格式安全：namespace、key、placeholder、`<Trans>` tag、非 string entry 都能被静态类型或 CI 发现。
4. 增量演进：新增语言、新增 namespace、修改默认文案、清理废弃 key 都有确定流程。

## 2. 非目标

本 SPEC 不负责：

1. 自动机器翻译质量。
2. 后端返回业务数据的翻译策略。
3. CMS 或远程翻译平台集成。
4. SEO 多语言路由，例如 `/en-US/...`、`/zh-CN/...`。如项目需要，可在本架构上增加 locale segment。

## 3. 架构原则

1. 默认语言使用 TypeScript 文件作为 source of truth。
2. 所有 locale JSON 都是派生产物或人工翻译产物，不作为 key 定义入口。
3. key 使用 flat dot notation，不使用嵌套 object。
4. `keySeparator` 必须关闭，避免 `a.b.c` 被 i18next 当作嵌套路径。
5. runtime 只接受受支持 locale；任何未知输入都归一化到默认语言。
6. 多语言资源缺失时 fallback 到默认语言，不能让 UI 显示 raw key。
7. CI 必须阻止 baseline 漂移、缺 key、额外 key、placeholder/tag mismatch。
8. React 组件只通过 `useTranslation` 或 `<Trans>` 获取文案，不直接 import locale JSON。
9. 日期、数字、货币、相对时间使用 `Intl`，不能手写格式化。
10. 语言切换必须同时更新 i18next、cookie、HTML attributes。

## 5. Locale 模型

`frontend/i18n/resources.ts`

```typescript
export const DEFAULT_LOCALE = "en-US";
export const LOCALE_COOKIE = "app-locale";

export const locales = ["en-US", "zh-CN", "ja-JP", "es-ES"] as const;
export type SupportedLocale = (typeof locales)[number];

const localeMap: Record<string, SupportedLocale> = {
  en: "en-US",
  "en-us": "en-US",
  zh: "zh-CN",
  "zh-cn": "zh-CN",
  "zh-hans": "zh-CN",
  ja: "ja-JP",
  "ja-jp": "ja-JP",
  es: "es-ES",
  "es-es": "es-ES",
};

export const normalizeLocale = (raw?: string): SupportedLocale => {
  if (!raw) return DEFAULT_LOCALE;

  const lower = raw.trim().toLowerCase();
  if (localeMap[lower]) return localeMap[lower];

  const prefix = lower.split(/[-_]/)[0];
  if (localeMap[prefix]) return localeMap[prefix];

  return DEFAULT_LOCALE;
};

export const isSupportedLocale = (raw: string): raw is SupportedLocale => {
  return (locales as readonly string[]).includes(raw);
};

const matchSupportedLocale = (raw?: string): SupportedLocale | null => {
  if (!raw) return null;

  const lower = raw.trim().toLowerCase();
  if (localeMap[lower]) return localeMap[lower];

  const prefix = lower.split(/[-_]/)[0];
  return localeMap[prefix] ?? null;
};

export const resolveAcceptLanguage = (header: string): SupportedLocale => {
  const candidates = header
    .split(",")
    .map((item) => {
      const [tag, ...params] = item.trim().split(";");
      const q = params
        .map((param) => param.trim())
        .find((param) => param.startsWith("q="))
        ?.slice(2);

      return {
        locale: matchSupportedLocale(tag),
        quality: q ? Number.parseFloat(q) : 1,
      };
    })
    .filter((item): item is { locale: SupportedLocale; quality: number } => {
      return item.locale !== null && Number.isFinite(item.quality);
    })
    .sort((a, b) => b.quality - a.quality);

  return candidates[0]?.locale ?? DEFAULT_LOCALE;
};

const rtlLanguageCodes = new Set(["ar", "he", "fa", "ur"]);

export const isRtl = (locale: string): boolean => {
  const prefix = locale.split(/[-_]/)[0].toLowerCase();
  return rtlLanguageCodes.has(prefix);
};
```

## 6. 请求层语言解析

Next.js 项目使用 `proxy.ts` 或 middleware 等价入口。解析优先级固定为：

1. URL query：`?hl=<locale>`
2. cookie：`app-locale`
3. request header：`Accept-Language`
4. `DEFAULT_LOCALE`

`frontend/proxy.ts`

```typescript
import { NextResponse, type NextRequest } from "next/server";
import { LOCALE_COOKIE, normalizeLocale, resolveAcceptLanguage } from "./i18n/locales";

export function proxy(request: NextRequest) {
  const url = new URL(request.url);
  const queryLocale = url.searchParams.get("hl") || undefined;
  const cookieLocale = request.cookies.get(LOCALE_COOKIE)?.value;
  const acceptLanguage = request.headers.get("accept-language") ?? "";
  const preferredLocale = resolveAcceptLanguage(acceptLanguage);

  const resolvedLocale = normalizeLocale(queryLocale || cookieLocale || preferredLocale);

  const requestHeaders = new Headers(request.headers);
  requestHeaders.set("x-locale", resolvedLocale);

  const response = NextResponse.next({
    request: {
      headers: requestHeaders,
    },
  });

  if (queryLocale || !cookieLocale) {
    response.cookies.set(LOCALE_COOKIE, resolvedLocale, {
      path: "/",
      maxAge: 365 * 86400,
      sameSite: "lax",
      secure: process.env.NODE_ENV === "production",
    });
  }

  return response;
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)"],
};
```

说明：

1. 若项目已有 auth/session middleware，locale header 写入必须保留已有 response cookies。
2. `?hl=` 应覆盖旧 cookie 并持久化，便于分享链接触发语言切换。
3. 不能把 unsupported locale 写进 cookie。
4. `Accept-Language` 必须按 `q` 值和候选顺序选择第一个受支持 locale，不能只取第一个 token。

## 7. Server Component 读取

`frontend/i18n/server.ts`

```typescript
import { cookies, headers } from "next/headers";
import type { SupportedLocale } from "./locales";
import { DEFAULT_LOCALE, LOCALE_COOKIE, normalizeLocale } from "./locales";

export async function getServerLocale(): Promise<SupportedLocale> {
  const headerStore = await headers();
  const hintedLocale = headerStore.get("x-locale");
  if (hintedLocale) return normalizeLocale(hintedLocale);

  const cookieStore = await cookies();
  const rawLocale = cookieStore.get(LOCALE_COOKIE)?.value;
  return rawLocale ? normalizeLocale(rawLocale) : DEFAULT_LOCALE;
}
```

`frontend/app/layout.tsx`

```tsx
import { isRtl } from "@/i18n/locales";
import { getServerLocale } from "@/i18n/server";
import { RootProvider } from "@/providers/root-provider";

export default async function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  const locale = await getServerLocale();

  return (
    <html lang={locale} dir={isRtl(locale) ? "rtl" : "ltr"} suppressHydrationWarning>
      <body>
        <RootProvider initialLocale={locale}>{children}</RootProvider>
      </body>
    </html>
  );
}
```

`lang`、`dir` 和 `RootProvider.initialLocale` 必须使用同一个 `locale`。不能只把 locale 写到 HTML 后再让 client i18n 自己从 `document` 推断；这会让 App Router 的 Client Component SSR 阶段退回默认语言，造成非默认语言首屏 hydration 分叉。

## 10. Client Provider

`frontend/i18n/client.tsx`

```tsx
"use client";

import { createContext, useContext, useMemo } from "react";
import { createInstance, type i18n as I18nInstance } from "i18next";
import resourcesToBackend from "i18next-resources-to-backend";
import { I18nextProvider, initReactI18next } from "react-i18next";

import enUS, { allNamespaces } from "@/locales/default";
import type { SupportedLocale } from "./locales";
import { DEFAULT_LOCALE, LOCALE_COOKIE, isRtl, normalizeLocale } from "./locales";
import { getI18nSettings } from "./settings";

interface I18nContextValue {
  i18n: I18nInstance;
  switchLang: (locale: string) => Promise<void>;
}

const I18nContext = createContext<I18nContextValue | null>(null);

function createI18nInstance(initialLocale: SupportedLocale): I18nInstance {
  const i18n = createInstance();
  i18n
    .use(initReactI18next)
    .use(
      resourcesToBackend(async (lng: string, ns: string) => {
        const normalizedLocale = normalizeLocale(lng);

        if (normalizedLocale === DEFAULT_LOCALE) {
          return enUS[ns as keyof typeof enUS] ?? {};
        }

        try {
          const mod = await import(`@/locales/${normalizedLocale}/${ns}.json`);
          return mod.default ?? mod;
        } catch {
          if (process.env.NODE_ENV !== "production") {
            console.warn(`Missing i18n namespace: ${normalizedLocale}/${ns}`);
          }
          return enUS[ns as keyof typeof enUS] ?? {};
        }
      }),
    )
    .init({
      ...getI18nSettings(initialLocale, allNamespaces),
      partialBundledLanguages: true,
      returnEmptyString: false,
      returnNull: false,
      react: {
        useSuspense: true,
      },
    });

  return i18n;
}

function writeLocaleCookie(locale: SupportedLocale): void {
  const secure = window.location.protocol === "https:" ? ";secure" : "";
  document.cookie = [
    `${LOCALE_COOKIE}=${encodeURIComponent(locale)}`,
    "path=/",
    `max-age=${365 * 86400}`,
    "samesite=lax",
  ].join(";") + secure;
}

export function I18nProvider({
  children,
  initialLocale,
}: {
  children: React.ReactNode;
  initialLocale: SupportedLocale;
}) {
  const i18n = useMemo(() => createI18nInstance(initialLocale), [initialLocale]);

  const value = useMemo<I18nContextValue>(() => {
    return {
      i18n,
      async switchLang(locale: string) {
        const normalizedLocale = normalizeLocale(locale);
        await i18n.changeLanguage(normalizedLocale);
        writeLocaleCookie(normalizedLocale);
        document.documentElement.lang = normalizedLocale;
        document.documentElement.dir = isRtl(normalizedLocale) ? "rtl" : "ltr";
      },
    };
  }, [i18n]);

  return (
    <I18nContext.Provider value={value}>
      <I18nextProvider i18n={i18n}>{children}</I18nextProvider>
    </I18nContext.Provider>
  );
}

export function useI18n() {
  const value = useContext(I18nContext);
  if (!value) throw new Error("useI18n must be used within I18nProvider");
  return value;
}
```

`frontend/providers/root-provider.tsx`

## 11. 语言切换

语言切换必须通过 `useI18n()` 获取当前 provider 内的 i18n instance。不要从模块级 singleton 导出 `switchLang`，否则 App Router SSR 和多请求场景容易共享错误状态。

推荐 UI 状态模型：

```tsx
"use client";

import { startTransition, useEffect, useState } from "react";
import { useI18n } from "@/i18n/client";
import { localeOptions, normalizeLocale } from "@/i18n/locales";

export function LanguageSelector() {
  const { i18n, switchLang } = useI18n();
  const [activeLocale, setActiveLocale] = useState(() => normalizeLocale(i18n.language));
  const [pendingLocale, setPendingLocale] = useState<string | null>(null);

  useEffect(() => {
    const syncLocale = (locale: string) => {
      setActiveLocale(normalizeLocale(locale));
    };

    i18n.on("languageChanged", syncLocale);

    return () => {
      i18n.off("languageChanged", syncLocale);
    };
  }, []);

  function selectLocale(locale: string) {
    if (pendingLocale || locale === activeLocale) return;

    setPendingLocale(locale);
    startTransition(() => {
      void switchLang(locale).finally(() => {
        setPendingLocale(null);
      });
    });
  }

  return (
    <div>
      {localeOptions.map((option) => (
        <button
          key={option.value}
          type="button"
          aria-pressed={activeLocale === option.value}
          disabled={pendingLocale === option.value}
          onClick={() => selectLocale(option.value)}
        >
          {option.label}
        </button>
      ))}
    </div>
  );
}
```

切换契约：

1. `switchLang` 必须先调用当前 provider 内的 `i18n.changeLanguage`。
2. 成功后写入 locale cookie。
3. 同步更新 `document.documentElement.lang`。
4. 同步更新 `document.documentElement.dir`。
5. UI 需要处理 pending 状态，避免快速连点造成乱序。

## 12. 组件使用规范

所有消费者都必须从当前 React i18n context 读取文案。React 组件使用 `useTranslation` 或 `<Trans>`；client event/helper 可以通过 `useI18n()` 拿到当前 provider 的 i18n instance；server/shared module 不能 import `@/i18n/client`。

普通文案：

```tsx
import { useTranslation } from "react-i18next";

export function SaveButton() {
  const { t } = useTranslation("common");

  return <button type="button">{t("action.save")}</button>;
}
```

带 placeholder：

```tsx
const { t } = useTranslation("common");

t("user.greeting", { name: user.name });
```

多 namespace：

```tsx
const { t } = useTranslation(["dashboard", "common"]);

t("dashboard:page.title");
t("common:action.save");
```

带 React node 的内容必须用 `<Trans>`：

```tsx
import { Trans } from "react-i18next";

<Trans
  ns="common"
  i18nKey="legal.accept"
  values={{
    productName: "App Name",
  }}
  components={{
    terms: <a href="/terms" />,
    privacy: <a href="/privacy" />,
  }}
/>;
```

`<Trans>` 规则：

1. 只使用 named components，不使用位置下标组件。
2. placeholder 通过 `values` 传入，不能字符串拼接。
3. translation string 只能引用显式传入的 component tag。
4. 禁止让翻译内容注入任意 HTML。
5. 动态列表不要放进 translation string；列表项自身再使用独立 key。

禁止模式：

```tsx
import zhCN from "@/locales/zh-CN/common.json";

const text = currentLocale === "zh-CN" ? zhCN["action.save"] : "Save";
```

反模式清单：

1. JSX 中直接写用户可见 hardcoded text。
2. 使用完整英文句子作为 key。
3. 使用 `t(dynamicKey)` 但没有 protected pattern 或类型约束。
4. 通过字符串拼接生成句子。
5. 使用 `defaultValue` 掩盖 missing key。
6. 按 `i18n.language` 分支返回不同文案。
7. server/shared module import `@/i18n/client`。
8. 手写日期、数字、货币、相对时间格式。
9. 使用 `dangerouslySetInnerHTML` 渲染翻译内容。
10. 把 `t` 包装成 `(key: string) => string` 导致类型信息丢失。

## 13. Key 命名规范

推荐形状：

```typescript
export default {
  "page.title": "Dashboard",
  "page.description": "Monitor your workspace.",
  "action.create": "Create",
  "action.delete": "Delete",
  "status.empty": "No items yet",
  "status.loading": "Loading...",
  "dialog.delete.title": "Delete item",
  "dialog.delete.description": "This action cannot be undone.",
  "form.email.label": "Email",
  "form.email.error.invalid": "Enter a valid email address.",
} as const;
```

规则：

1. 使用 `{surface}.{context}.{role}` 或 `{feature}.{state}.{role}`。
2. `action.*` 用于按钮和命令。
3. `status.*` 用于 loading、empty、success、error。
4. `dialog.*` 用于 modal。
5. `form.*` 用于 label、placeholder、error。
6. key 不使用完整英文句子。
7. key 不复用不同语义。
8. 不允许一个 key 同时作为 leaf 和 prefix。
9. `common` 只放跨业务域语义完全一致的基础 UI 文案。
10. 业务语义必须留在 feature namespace，不能为了省翻译复用近义 key。

错误示例：

```typescript
export default {
  "save": "Save",
  "dashboard": "Dashboard",
  "dashboard.title": "Dashboard",
} as const;
```

修正示例：

```typescript
export default {
  "action.save": "Save",
  "dashboard.label": "Dashboard",
  "dashboard.title": "Dashboard",
} as const;
```

## 14. Placeholder 与 Trans 约束

placeholder 使用 `{{variableName}}`：

```typescript
export default {
  "invite.description": "{{senderName}} invited you to {{workspaceName}}.",
} as const;
```

所有 locale 必须保留完全相同 placeholder set：

```json
{
  "invite.description": "{{senderName}} invited you to {{workspaceName}}."
}
```

`<Trans>` tag 必须保留 tag set：

```typescript
export default {
  "notice.contact": "Contact <email>{{email}}</email> for help.",
} as const;
```

```json
{
  "notice.contact": "Contact <email>{{email}}</email> for help."
}
```

CI 必须检查：

1. baseline 有 placeholder，目标 locale 不能丢。
2. 目标 locale 不能新增 baseline 没有的 placeholder。
3. baseline 有 `<email>`，目标 locale 必须保留 `<email>`。
4. `<br>` 可以作为自闭合展示 tag，不参与 tag mismatch。

## 15. Plural、context 与格式化

复数使用 i18next plural key。默认至少提供 `_one` 和 `_other`；支持多复数类别语言时，必须按 `Intl.PluralRules(locale).resolvedOptions().pluralCategories` 或项目显式 plural policy 补齐该 locale 需要的 category。

```typescript
export default {
  "item.count_one": "{{count}} item",
  "item.count_other": "{{count}} items",
} as const;
```

```tsx
t("item.count", { count });
```

plural 约束：

1. 同一个 plural family 的所有 key 必须保留 `{{count}}`。
2. `i18n:check` 必须能报告 locale-specific plural category 缺失。
3. report reason 使用 `plural_mismatch`。
4. 测试 fixture 至少覆盖 English 这类 `one/other` 语言，以及 Arabic/Russian 这类多 category 语言。

日期、数字、货币、相对时间用 `Intl`：

```typescript
export function formatDate(value: Date, locale: string): string {
  return new Intl.DateTimeFormat(locale, {
    dateStyle: "medium",
    timeStyle: "short",
  }).format(value);
}

export function formatNumber(value: number, locale: string): string {
  return new Intl.NumberFormat(locale).format(value);
}

export function formatCurrency(value: number, locale: string, currency: string): string {
  return new Intl.NumberFormat(locale, {
    currency,
    style: "currency",
  }).format(value);
}

export function formatRelativeTime(value: number, unit: Intl.RelativeTimeFormatUnit, locale: string): string {
  return new Intl.RelativeTimeFormat(locale, {
    numeric: "auto",
  }).format(value, unit);
}
```

规范：

1. 不把动态日期、数字格式写进 translation string。
2. 只把静态语义文案放进 i18n resource。
3. 复杂单位可用 i18next 文案包住已格式化值。
4. SSR 和 client 必须使用同一 timezone policy；跨时区产品要显式传入 timezone。
5. React 中 formatter 应随 locale 变化重建，例如通过 `useMemo` 依赖 `i18n.language`。

## 16. Metadata 与非 React 文案

Next.js metadata 需要 server-side locale-aware helper：

```typescript
import type { Metadata } from "next";
import type { SupportedLocale } from "@/i18n/locales";
import { getServerLocale } from "@/i18n/server";

const metadataByLocale = {
  "en-US": {
    title: "App Name",
    description: "Product description.",
  },
  "zh-CN": {
    title: "App Name",
    description: "Product description.",
  },
  "ja-JP": {
    title: "App Name",
    description: "Product description.",
  },
  "es-ES": {
    title: "App Name",
    description: "Product description.",
  },
} satisfies Record<SupportedLocale, Metadata>;

export async function generateMetadata(): Promise<Metadata> {
  const locale = await getServerLocale();
  return metadataByLocale[locale];
}
```

client 非 React 场景，例如 event handler 或 client-only helper，可以通过 `useI18n()` 获取当前 provider 的 instance：

```tsx
import { useI18n } from "@/i18n/client";

export function ClientAction() {
  const { i18n } = useI18n();
  return i18n.t("action.save", { ns: "common" });
}
```

server、route handler、server action、metadata、shared module 禁止 import `@/i18n/client`。服务端非 React 文案应使用 server-only helper：

`frontend/i18n/server-instance.ts`

```typescript
import { createInstance } from "i18next";
import resourcesToBackend from "i18next-resources-to-backend";

import enUS from "@/locales/default";
import type { SupportedLocale } from "./locales";
import { DEFAULT_LOCALE, normalizeLocale } from "./locales";
import { getI18nSettings } from "./settings";

export async function createServerI18n(locale: SupportedLocale, ns: string | string[]) {
  const i18n = createInstance();

  await i18n
    .use(
      resourcesToBackend(async (lng: string, namespace: string) => {
        const normalizedLocale = normalizeLocale(lng);

        if (normalizedLocale === DEFAULT_LOCALE) {
          return enUS[namespace as keyof typeof enUS] ?? {};
        }

        try {
          const mod = await import(`@/locales/${normalizedLocale}/${namespace}.json`);
          return mod.default ?? mod;
        } catch {
          return enUS[namespace as keyof typeof enUS] ?? {};
        }
      }),
    )
    .init(getI18nSettings(locale, ns));

  return i18n;
}
```

边界规则：

1. client code 使用 `useTranslation`、`<Trans>`、`useI18n()`。
2. server code 使用 `getServerLocale()` 和 `createServerI18n()`。
3. shared module 不直接读 i18n；由 caller 注入已翻译字符串或 formatter。
4. metadata 必须覆盖全部 `SupportedLocale`，除非显式采用 `Partial<Record<SupportedLocale, Metadata>>` 并在测试中审查 fallback。

## 17. 翻译工作流脚本契约

所有 i18n workflow 命令默认从 `frontend/` 目录执行。如果 CI 从 monorepo root 执行，必须使用 `pnpm --dir frontend <script>`，并且所有 `git diff` 路径必须带 `frontend/` 前缀。

`frontend/scripts/i18nWorkflow/config.ts`

```typescript
export interface I18nWorkflowConfig {
  defaultLocale: string;
  localesDir: string;
  sourceLocaleDir: string;
  sourceLocaleIndex: string;
}

export const i18nWorkflowConfig: I18nWorkflowConfig = {
  defaultLocale: "en-US",
  localesDir: "locales",
  sourceLocaleDir: "locales/default",
  sourceLocaleIndex: "locales/default/index.ts",
};
```

`package.json` scripts：

```json
{
  "scripts": {
    "i18n": "tsx ./scripts/i18nWorkflow/index.ts",
    "i18n:diff": "tsx ./scripts/i18nWorkflow/genDiff.ts",
    "i18n:gen-default": "tsx ./scripts/i18nWorkflow/genDefaultLocaleJson.ts",
    "i18n:check": "tsx ./scripts/i18nWorkflow/checkTranslations.ts",
    "i18n:init-locale": "tsx ./scripts/i18nWorkflow/initLocale.ts",
    "i18n:analyze-unused": "tsx ./scripts/i18nWorkflow/analyzeUnusedKeys.ts",
    "i18n:clean-unused": "tsx ./scripts/i18nWorkflow/cleanUnusedKeys.ts"
  }
}
```

脚本职责：

1. `i18n:gen-default`：读取 `locales/default/index.ts`，生成 `locales/en-US/*.json`。
2. `i18n:diff`：读取当前 `locales/en-US/*.json` 作为 previous baseline，读取 `locales/default/*.ts` 作为 next source。它必须在 `i18n:gen-default` 之前运行；否则无法识别 key 不变但英文 value 已变的情况。
3. `i18n:check`：检查所有非 default locale 的完整性和格式。
4. `i18n:init-locale <locale>`：为目标 locale 创建缺失的 namespace JSON 文件，默认写入 `{}`，保留已有文件和已有翻译；如果 locale 尚未加入 `resources.ts`，必须失败。
5. `i18n:analyze-unused`：扫描源码中使用的 key，输出 unused report。
6. `i18n:clean-unused`：基于 unused report 清理非默认 locale JSON；默认 dry run。它不删除 `locales/default/*.ts` 中的 source key。
7. `i18n`：运行 `i18n:diff` 后运行 `i18n:gen-default`。

`i18n:diff` 的行为契约：

1. 如果 key 新增，只由 `i18n:check` 报告其他 locale 的 `missingKeys`。
2. 如果 key 删除，`i18n:check` 报告其他 locale 的 `extraKeys`。
3. 如果 key 保持不变但 default value 改变，`i18n:diff` 必须从非默认 locale JSON 删除该 key 或清空该 key，使 `i18n:check` 重新报告翻译需求。
4. `i18n:diff` 不能在 `i18n:gen-default` 之后运行。
5. `i18n` 聚合命令的顺序必须固定为 `diff -> gen-default`。

## 18. Report 格式

`i18n-missing-report.json`

```json
{
  "generatedAt": "2026-01-01T00:00:00.000Z",
  "summary": {
    "locales": 3,
    "namespaces": 4,
    "missingKeys": 2,
    "extraKeys": 1,
    "invalidEntries": 1
  },
  "reports": [
    {
      "locale": "zh-CN",
      "namespace": "common",
      "filePath": "locales/zh-CN/common.json",
      "missingKeys": ["action.save"],
      "extraKeys": ["old.key"],
      "invalidEntries": [
        {
          "key": "user.greeting",
          "reason": "placeholder_mismatch",
          "expectedPlaceholders": ["name"],
          "actualPlaceholders": [],
          "baselineValue": "Hello, {{name}}",
          "currentValue": "Hello"
        }
      ]
    }
  ]
}
```

`invalidEntries.reason` 枚举：

1. `placeholder_mismatch`
2. `tag_mismatch`
3. `non_string_value`
4. `plural_mismatch`

`invalidEntries` 字段约束：

1. `placeholder_mismatch` 使用 `expectedPlaceholders` 和 `actualPlaceholders`。
2. `tag_mismatch` 使用 `expectedTags` 和 `actualTags`。
3. `non_string_value` 使用 `actualType`。
4. `plural_mismatch` 使用 `expectedPluralCategories` 和 `actualPluralCategories`。
5. `baselineValue` 和 `currentValue` 推荐输出，便于 reviewer 和翻译 Agent 定位。

翻译 Agent patch contract：

1. 只能编辑 `locales/<locale>/*.json`。
2. 只能新增 `missingKeys` 中列出的 key。
3. 只能删除 `extraKeys` 中列出的 key。
4. 只能修复 `invalidEntries` 中列出的 key。
5. 必须保留 placeholder、tag 和 plural family 结构。
6. 不能修改 `locales/default/*.ts` 或 `locales/en-US/*.json`，除非任务明确是 authoring 或 baseline generation。

CI 规则：

1. `summary.missingKeys === 0`
2. `summary.extraKeys === 0`
3. `summary.invalidEntries === 0`

## 19. 常规操作手册

新增文案：

1. 修改 `frontend/locales/default/{namespace}.ts`。
2. 若是新 namespace，加入 `frontend/locales/default/index.ts`。
3. 运行 `pnpm i18n:gen-default`。
4. 运行 `pnpm i18n:check`。
5. 根据 `i18n-missing-report.json` 补其他 locale JSON。
6. 再运行 `pnpm i18n:check`，直到报告为空。

修改默认英文文案：

1. 修改 `frontend/locales/default/{namespace}.ts`。
2. 运行 `pnpm i18n`。
3. 运行 `pnpm i18n:check`。
4. 只补报告列出的 locale/key。

新增语言：

1. 修改 `frontend/i18n/resources.ts`，加入 locale 和 alias。
2. 修改 `frontend/i18n/options.ts`，加入语言选项。
3. 运行 `pnpm i18n:gen-default`。
4. 运行 `pnpm i18n:init-locale <locale>`。
5. 运行 `pnpm i18n:check`。
6. 填充报告中的 missing keys。
7. 验证语言切换 UI、HTML `lang`、cookie、动态 import。

删除文案：

1. 搜索并删除所有 `t()`、`<Trans>`、server helper 对该 key 的引用。
2. 删除 `frontend/locales/default/{namespace}.ts` 中的 key。
3. 运行 `pnpm i18n:gen-default`。
4. 运行 `pnpm i18n:check`。
5. 删除报告中的 `extraKeys`。

清理废弃 key：

1. 运行 `pnpm i18n:analyze-unused`。
2. 人工审查 `i18n-unused-keys-report.json`。
3. 对动态 key 增加 protected pattern。
4. 从 `frontend/locales/default/{namespace}.ts` 删除确认废弃的 source key。
5. 运行 `pnpm i18n:gen-default`。
6. 运行 `pnpm i18n:check`。
7. 运行 `pnpm i18n:clean-unused` 做 dry run。
8. 确认后运行 `pnpm i18n:clean-unused --no-dry-run`。

## 20. CI 与 PR Gate

每个 PR 至少运行：

```bash
pnpm --dir frontend lint
pnpm --dir frontend i18n:gen-default
git diff --exit-code -- frontend/locales/en-US
pnpm --dir frontend i18n:check
pnpm --dir frontend test
pnpm --dir frontend typecheck
```

如果 CI 工作目录已经是 `frontend/`，等价命令是：

```bash
pnpm lint
pnpm i18n:gen-default
git diff --exit-code -- locales/en-US
pnpm i18n:check
pnpm test
pnpm typecheck
```

CI 失败场景：

1. default TS 未同步到 `en-US` JSON。
2. 非默认 locale 缺 key。
3. 非默认 locale 有多余 key。
4. placeholder 不一致。
5. `<Trans>` tag 不一致。
6. locale JSON value 不是 string。
7. plural family category 不完整。
8. 类型测试发现非法 key、非法 namespace、缺失 interpolation 或错误 interpolation。

## 21. 测试矩阵

单元测试：

1. `normalizeLocale`：
   - `undefined -> en-US`
   - `en -> en-US`
   - `zh-Hans -> zh-CN`
   - unsupported input -> `en-US`
2. `isRtl`：
   - `ar -> true`
   - `en-US -> false`
3. `switchLang`：
   - calls `i18n.changeLanguage`
   - writes cookie
   - updates `document.documentElement.lang`
   - updates `document.documentElement.dir`
4. `resolveAcceptLanguage`：
   - `fr-CA,zh-CN;q=0.9,en-US;q=0.8 -> zh-CN`
   - `es-ES,zh-CN;q=0.9 -> es-ES`
   - unsupported-only header -> `en-US`
5. `createServerI18n`：
   - returns requested namespace for current locale
   - falls back to default locale when namespace JSON is missing
   - never imports `@/i18n/client`

集成测试：

1. 首次访问无 cookie，使用 `Accept-Language`。
2. 带 `?hl=zh-CN`，覆盖当前 cookie。
3. 带 cookie 时忽略 `Accept-Language`。
4. 客户端切换语言后，页面文案更新且刷新后保持。
5. 缺失 namespace JSON 时 fallback 到默认语言。
6. `<Trans>` 渲染链接、按钮等 React node 正常。
7. `RootLayout` 传入的 `initialLocale`、HTML `lang`、HTML `dir` 一致。
8. 非默认 locale 首屏 SSR 不退回默认语言。
9. metadata 覆盖全部 `SupportedLocale`。

workflow fixture 测试：

1. `i18n:check` reports missing key。
2. `i18n:check` reports extra key。
3. `i18n:check` reports placeholder mismatch。
4. `i18n:check` reports tag mismatch。
5. `i18n:check` reports non-string value。
6. `i18n:check` reports plural mismatch。
7. `i18n:diff` detects default value changes before baseline regeneration。
8. `i18n:init-locale` preserves existing translations and creates missing namespace files。
9. `i18n:analyze-unused` respects protected patterns。

类型测试：

1. invalid key fails typecheck。
2. invalid namespace fails typecheck。
3. missing interpolation value fails typecheck when supported by the i18next type setup。
4. wrong interpolation name fails typecheck when supported by the i18next type setup。
5. wrappers do not erase `TFunction` generics。

人工 QA：

1. 语言切换 UI 不闪 raw key。
2. 日期、数字、货币随 locale 变化。
3. HTML `lang` 正确。
4. RTL 语言下 HTML `dir` 正确。
5. SEO metadata 与当前 locale 一致。

## 22. SSR、Suspense 与 Hydration 注意事项

1. App Router 中 `RootLayout` 解析 locale，并把同一个 locale 写入 `<html lang>`、`<html dir>` 和 `RootProvider.initialLocale`。
2. `suppressHydrationWarning` 是必要保护，但不能掩盖语言解析不一致。
3. `I18nProvider` 必须使用 `initialLocale` 创建当前 provider 内的 i18n instance，不能在 module scope 通过 `document` 推断语言。
4. `react.useSuspense: true` 时，RootProvider 或 route segment 必须提供明确的 `<Suspense>` fallback。
5. 若首屏有大量动态 namespace，可预加载关键 namespace 或把首屏 namespace 放入 default resource。
6. 不要在 Server Component 中调用 client i18n instance。
7. 不要在 module scope 读取 `document`。
8. dynamic import fallback 可以保护 UI，但 development/test 环境必须记录 missing namespace，避免路径错误被静默吞掉。

## 23. 安全与隐私

1. locale cookie 不存放用户敏感信息。
2. locale query 参数只允许归一化后的支持值。
3. 翻译字符串不能包含未经审查的 HTML。
4. `<Trans>` 只允许明确传入的 React components。
5. 用户输入必须作为 interpolation value 传入，不拼接进 translation resource。

## 24. 性能策略

1. 默认语言直接打包，避免首屏多一次 JSON import。
2. 非默认语言按 namespace 动态加载。
3. namespace 要按 feature 拆分，避免巨大 `common`。
4. 高频基础文案放 `common`。
5. 不为单个组件建立过细 namespace。
6. 大型模块可独立 namespace，例如 `agentConversation`、`workflows`、`billing`。
7. CI 监控 namespace key 数，发现异常膨胀时拆分。
