## Purpose / Big Picture

Cradle Desktop needs a macOS-native bridge that can observe a user gesture, capture the currently active app window, and optionally pass the captured image to another tool such as CleanShot without making that tool a hard dependency. After this change, a user or developer can run the desktop main process against a bundled or development `cradle-mac-bridge` binary, ask the bridge for permission status, trigger a frontmost-window capture through Electron IPC, and select a post-capture sink such as saving the file, copying it to the clipboard, or opening it in CleanShot if CleanShot is installed.

The feature is called Mac Bridge, not System Agent. An agent in this repository means an autonomous runtime that can plan or act on a user goal. Mac Bridge is not autonomous and does not own product semantics. It is a desktop-owned sidecar process that translates explicit desktop requests into macOS API calls.

## Surprises & Discoveries

- Observation: The repository already has a Chronicle Rust daemon that captures screen and accessibility evidence, but it is semantically owned by `apps/server/src/modules/chronicle`.
  Evidence: `chronicle/src/README.md` says Chronicle reports snapshots, accessibility evidence, memories, and audio transcripts to Chronicle APIs, while `apps/server/src/modules/chronicle/daemon-manager.ts` starts `cradle-chronicle` from the server module.
- Observation: The Electron desktop runtime already has a child-process lifecycle pattern in `apps/desktop/src/main/server-process.ts`.
  Evidence: It resolves dev and packaged entries, starts the server child, prefixes logs, bounds restarts, and shuts down on quit.
- Observation: The initial plan accidentally used `agent.status` for the bridge status method even though the feature name intentionally avoids agent terminology.
  Evidence: The first draft of this file listed `agent.status` in `Concrete Steps` and `Interfaces and Dependencies`.
- Observation: The current desktop package config has no native helper resource slot for Mac Bridge.
  Evidence: `apps/desktop/electron-builder.yml` includes `extraResources` for server, drizzle, and browser-use plugin resources, but nothing for `native/macos` or `cradle-mac-bridge`.
- Observation: The desktop build script currently does not compile Swift helpers.
  Evidence: `apps/desktop/package.json` build runs server build, browser-use build, server native rebuild, and `electron-vite build`; it has no Mac Bridge build script.
- Observation: macOS permission status is observable and currently blocks the final hotkey smoke on this machine.
  Evidence: Manual `mac.permissions.status` returned `{"accessibility":"denied","inputMonitoring":"denied","screenRecording":"granted"}`. Manual `mac.input.configure` with `enabled: true` returns success, but without Input Monitoring/Accessibility grant there is no valid evidence that real both-Command key events can be observed.
- Observation: The first hotkey implementation used AppKit `flagsChanged` monitors and aggregate Command state, which is too weak for left/right Command semantics.
  Evidence: Reviewer round 4 found that releasing one Command key while another remains down can be misinterpreted if only aggregate `.command` state is used. The implementation was changed to a listen-only `CGEventTap` and device-specific left/right Command flag bits.
- Observation: The first default capture output directory used `system-captures`, which weakened the naming boundary.
  Evidence: Reviewer round 1 flagged the directory as reintroducing the rejected system terminology. The path is now `app.getPath('userData')/mac-captures`.
- Observation: The original implementation could read permission status but could not actively help the user escape a denied Input Monitoring or Accessibility state.
  Evidence: `mac.permissions.status` reported `inputMonitoring=denied` and `accessibility=denied`; after adding `mac.permissions.request` and `mac.permissions.openSettings`, the same bridge binary returned all three permissions as `granted`.
- Observation: Copying the release sidecar directly over `.build/cradle-dist/cradle-mac-bridge` can break the development binary path when an Electron dev app is already running the old binary.
  Evidence: The release binary and copied dist binary had matching SHA-256 hashes, but the dist path exited with status 137 while a dev Electron process held the old sidecar. Rebuilding with a temporary `.next` file followed by `renameSync` restored stable `bridge.status` and permission responses from the dist path.

## Context and Orientation

Cradle Desktop is an Electron application under `apps/desktop`. The main process starts in `apps/desktop/src/main/index.ts`, then loads `apps/desktop/src/main/main-app.ts`. The main process creates windows, starts the server child process, activates desktop plugins, owns tray lifecycle, and registers native IPC services through `apps/desktop/src/main/native-services.ts`.

An IPC service in this repository is a TypeScript class that extends `IpcService` from `packages/ipc/src/base.ts`. A service sets a static `groupName` and annotates methods with `@IpcMethod()`. Renderer code calls these methods through `createIpcProxy` in `apps/web/src/lib/electron.ts`, using channel names like `native.showOpenDialog` and `desktopUpdate.getStatus`.

A sidecar process is a separate executable started by the Electron main process. The existing server child process in `apps/desktop/src/main/server-process.ts` is the closest local pattern. Mac Bridge should follow this pattern but stay smaller: resolve the binary, spawn it when available, send NDJSON requests to stdin, parse NDJSON responses and events from stdout, prefix stderr logs, shut down on app quit, and avoid crashing the desktop if the binary is absent.

Chronicle is a separate Rust capability under `chronicle` and `apps/server/src/modules/chronicle`. It captures and summarizes evidence for memory. Mac Bridge may later become one input source for Chronicle, but this plan intentionally keeps Mac Bridge desktop-owned.

NDJSON means newline-delimited JSON: each line is a full JSON object. Requests from TypeScript have an `id`, `method`, and optional `params`. Responses from Swift have the same `id`, either `result` or `error`, and no event method. Events from Swift have a `method` beginning with `event.` and `params`, but no `id`.

## Plan of Work

First, create the Swift package at `apps/desktop/native/macos/mac-bridge`. The executable target is `CradleMacBridge`, and the product name is `cradle-mac-bridge`. The CLI reads stdin line by line, handles requests, and writes JSON responses. It implements `bridge.status`, `mac.permissions.status`, `mac.permissions.request`, `mac.permissions.openSettings`, `mac.input.configure`, and `mac.capture.frontmostWindow`. The first capture implementation identifies the frontmost application with `NSWorkspace`, finds an on-screen CoreGraphics window for that app, runs `/usr/sbin/screencapture -x -l <window-id> <output-path>`, writes a metadata JSON file next to the PNG, and returns paths and window metadata. The input monitor must distinguish left and right Command key state and emit `event.mac.hotkeyTriggered` only when both Command keys are down at the same time, with debounce so holding the keys does not create repeated captures.

Second, add TypeScript protocol and manager files under `apps/desktop/src/main`. `mac-bridge-protocol.ts` owns Zod schemas and TypeScript types. `mac-bridge-manager.ts` owns process resolution, spawn, request/response tracking, timeouts, event dispatch, and shutdown. It must be safe on non-macOS platforms and when the bridge binary is missing.

Third, add `mac-screenshot-sinks.ts`. The default sink returns the captured file path. The clipboard sink uses Electron clipboard APIs. The CleanShot sink only opens the CleanShot URL scheme with an encoded file path; it must not make CleanShot required and must fail independently from capture.

Fourth, add a desktop IPC service that exposes permission status, bridge status, frontmost capture, and hotkey configuration. The service should live in `apps/desktop/src/main/native-services.ts` or a narrow helper imported there. The renderer-facing service group should be named `macCapture`, because it is specific to this desktop capture workflow and avoids generic system terminology.

Fifth, wire the manager into `apps/desktop/src/main/main-app.ts`. It should be created before native IPC services are registered, started after `app.whenReady()` on macOS, and stopped during `shutdownDesktopRuntime()`. If startup fails because the binary is missing, the app should continue running and the IPC status should report `available: false`.

Sixth, add build and package integration. Add a desktop-owned script, likely `apps/desktop/scripts/build-mac-bridge.mjs`, that runs `swift build -c release` in `apps/desktop/native/macos/mac-bridge`, atomically replaces the deterministic generated binary at `apps/desktop/native/macos/mac-bridge/.build/cradle-dist/cradle-mac-bridge`, and skips with an explicit message on non-macOS hosts. Add a desktop package script such as `build:mac-bridge`, call it from `apps/desktop/package.json` `build`, and add `electron-builder.yml` `extraResources` so packaged macOS apps contain the bridge under `Contents/Resources/mac-bridge/cradle-mac-bridge`. The TypeScript manager must resolve development binaries from the Swift package build output and packaged binaries from `process.resourcesPath`.

Finally, update desktop README documentation and add tests. Focused tests should cover protocol schema parsing, manager behavior with a missing binary or fake process, CleanShot URL construction, and binary path resolution for development and packaged modes. Run TypeScript typecheck and targeted Vitest tests. If Swift is available, run `swift build` in the package directory and record the result. After implementation and initial validation, run five reviewer plus fix rounds. Each reviewer round must write a dated entry in this ExecPlan with verdict, evidence, blockers, and fixes applied. All five reviewer rounds must pass before the goal can be called complete.

## Idempotence and Recovery

The plan is additive. Creating the Swift package and TypeScript files can be repeated safely. The bridge writes screenshots only to a caller-provided output directory, and TypeScript will use a Cradle-owned directory under `app.getPath('userData')`. If the bridge process crashes or exits, the manager should reject in-flight requests, clear internal state, and allow a later start attempt. If the Swift binary is missing, no files are deleted and the desktop app continues without capture features. Rebuilding the release sidecar is safe while a dev Electron app is running because `build-mac-bridge.mjs` writes a temporary `.next` file and then renames it over the packaging output path.

No destructive Git operations are required. Existing unrelated worktree changes must not be reverted.
