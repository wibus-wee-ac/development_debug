# Bundle Code Splitting via TanStack Router Lazy Routes

This ExecPlan is a living document. The sections Progress, Surprises & Discoveries, Decision Log, and Outcomes & Retrospective must be kept up to date as work proceeds. This document must be maintained in accordance with docs/exec-plans/README.md and the PLANS.md conventions.

## Purpose / Big Picture

Currently, every route in the application is eagerly imported at startup. The generated route tree at `src/renderer/src/routeTree.gen.ts` statically imports all route modules, meaning the chat page (which pulls in xterm, AI SDK, virtual scrolling), the workspace detail page (Tiptap, Shiki, ProseMirror), and the kanban page (dnd-kit) are all parsed and compiled on first load — even if the user only visits the home dashboard.

After this change, heavy route components are lazy-loaded. Navigating to `/chat/$sessionId` for the first time triggers a dynamic import of the chat bundle. The home page and app shell load instantly. The user sees a brief loading indicator when first visiting a heavy route, then subsequent visits are cached. Total initial JS parse time drops significantly.

The `electron.vite.config.ts` already has `autoCodeSplitting: true` on the TanStack Router plugin, but it has no effect because no routes use the lazy file convention. This plan activates it by creating `.lazy.tsx` files for heavy routes.

## Context and Orientation

The application uses TanStack Router with file-based routing. Route files live in `src/renderer/src/routes/`. The Vite plugin `@tanstack/router-plugin/vite` (configured in `electron.vite.config.ts` at line 52) automatically generates `src/renderer/src/routeTree.gen.ts` from these files.

TanStack Router supports code splitting through "lazy route files". The convention is: if a route is defined at `routes/foo.tsx`, the lazy portion goes in `routes/foo.lazy.tsx`. The non-lazy file exports the `Route` object with loaders, search params, and context. The lazy file exports the `component`, `pendingComponent`, and `errorComponent` using `createLazyFileRoute`. The plugin's `autoCodeSplitting: true` automatically moves the component export to a lazy chunk when a `.lazy.tsx` file exists.

Current route files and their approximate bundle weight:

1. `chat.$sessionId.tsx` — HEAVY: xterm (8 addons), @ai-sdk/react, ai, streamdown, virtua, motion/react, fzf. This is by far the heaviest route.

2. `workspace.$workspaceId.tsx` — HEAVY: @tiptap/* (starter-kit + 7 extensions), shiki (bundled languages), ProseMirror ecosystem.

3. `kanban.tsx` + `kanban.$boardId.tsx` — MEDIUM: @dnd-kit/core, @dnd-kit/sortable, @dnd-kit/modifiers.

4. `index.tsx` — LIGHT: Home dashboard, should stay eagerly loaded as the landing page.

5. `devtool.tsx` — LIGHT but dev-only: superjson, custom components.

6. `new-chat.tsx` — MEDIUM: motion/react, Combobox. Could be lazy but benefit is marginal.

7. `settings.tsx` — Redirect only, no component weight.

The root layout at `__root.tsx` provides theme, toast, and shortcut providers and must remain eagerly loaded.

## Plan of Work

The key insight is that TanStack Router's `autoCodeSplitting` requires splitting each route file into two parts: the route definition (params, loaders, search params) stays in the original file, and the `component` export moves to a `.lazy.tsx` file. The Vite plugin then generates dynamic imports in `routeTree.gen.ts` automatically.

Milestone 1 handles the two heaviest routes: chat and workspace-detail. For each, the original route file keeps the `createFileRoute` call with its `component` property removed, and a new `.lazy.tsx` file exports the component via `createLazyFileRoute`.

Milestone 2 does the same for kanban routes.

Milestone 3 adds a shared `pendingComponent` (a minimal loading spinner) that shows while lazy chunks are being loaded.

Milestone 4 verifies that the Vite build produces separate chunks and that navigation works correctly with the loading states.

Milestone 5 optionally lazy-loads the devtool route (low priority since it is dev-only).

## Concrete Steps

Milestone 1: Chat and Workspace-Detail lazy routes

For `src/renderer/src/routes/chat.$sessionId.tsx`:

The current file exports a Route created with `createFileRoute` that has a `component` property pointing to the chat page component. Split this into two files:

`chat.$sessionId.tsx` (keep):

    import { createFileRoute } from '@tanstack/react-router'
    // Keep: search params validation, beforeLoad, loader, etc.
    // Remove: component export — it moves to the lazy file.

    export const Route = createFileRoute('/chat/$sessionId')({
      validateSearch: (search) => ({ tearoff: search.tearoff === true }),
      // no component here
    })

`chat.$sessionId.lazy.tsx` (new):

    import { createLazyFileRoute } from '@tanstack/react-router'

    // All the heavy imports (ChatView, AppLayout, etc.) are now in the lazy file
    import { ChatSessionPage } from '@renderer/features/chat/chat-session-page'

    export const Route = createLazyFileRoute('/chat/$sessionId')({
      component: ChatSessionPage,
      pendingComponent: RouteLoadingFallback,
    })

Repeat the same pattern for `workspace.$workspaceId.tsx`.

After creating both lazy files, regenerate the route tree by running the Vite dev server or `pnpm exec tsr generate`. The generated `routeTree.gen.ts` should now contain dynamic `import()` calls for these routes instead of static imports.

Milestone 2: Kanban lazy routes

Apply the same split to `kanban.tsx` (layout) and `kanban.$boardId.tsx` (board view). The kanban layout provides a sidebar, so the layout stays eagerly loaded but the board view component moves to lazy.

Actually, for `kanban.tsx`, since it is a layout route with an `<Outlet />`, the component should stay in the lazy file since layouts also benefit from code splitting. The route itself just defines the path.

Milestone 3: Loading fallback

Create a shared `RouteLoadingFallback` component at `src/renderer/src/components/common/route-loading-fallback.tsx`:

    export function RouteLoadingFallback() {
      return (
        <div className="flex h-full items-center justify-center">
          <Loader2Icon className="size-4 animate-spin text-muted-foreground/40" />
        </div>
      )
    }

Use this as the `pendingComponent` in all lazy route files.

Milestone 4: Validate code splitting

Run `pnpm build` and inspect the `out/renderer/` output. There should be multiple JS chunks instead of a single bundle. The chat-related chunk should contain xterm, AI SDK, etc. The workspace-detail chunk should contain Tiptap and Shiki.

Test by launching the app, observing that the home page loads without loading chat or workspace-detail code. Navigate to a chat session and verify the loading fallback appears briefly, then the chat page renders. Navigate to a workspace and verify the same.

Milestone 5: Devtool lazy route (optional)

Apply the same pattern to `devtool.tsx`. This is low priority since the devtool is only used during development.

## Validation and Acceptance

1. Running `pnpm build` produces multiple JS chunks in the renderer output directory (at least 3 separate chunks for chat, workspace-detail, and kanban).
2. The home page (`/`) loads without importing xterm, Tiptap, Shiki, or dnd-kit code.
3. Navigating to `/chat/$sessionId` shows a brief spinner then the chat page.
4. Navigating to `/workspace/$workspaceId` shows a brief spinner then the workspace detail page.
5. Navigating to `/kanban/$boardId` shows a brief spinner then the kanban board.
6. Subsequent navigations to already-loaded routes are instant (no spinner).
7. All existing functionality (streaming, editing, drag-and-drop) works unchanged.

## Idempotence and Recovery

All changes are additive — new `.lazy.tsx` files alongside existing route files. If a lazy file causes issues, deleting it and restoring the `component` property in the original route file reverts to eager loading. The route tree regenerates automatically on file system changes.

## Artifacts and Notes

TanStack Router lazy route pattern reference:

    // routes/foo.tsx (non-lazy, keeps params/loader/search)
    export const Route = createFileRoute('/foo')({
      validateSearch: (s) => ({ ... }),
      loader: async () => { ... },
    })

    // routes/foo.lazy.tsx (lazy, keeps component/pending/error)
    export const Route = createLazyFileRoute('/foo')({
      component: FooPage,
      pendingComponent: () => <Loading />,
      errorComponent: ({ error }) => <Error error={error} />,
    })

The Vite plugin with `autoCodeSplitting: true` detects the `.lazy.tsx` file and generates:

    const FooLazyRoute = FooRoute.update({
      ...FooRouteImport,
      getParentRoute: () => rootRoute,
    } as any).lazy(() => import('./routes/foo.lazy').then(d => d.Route))
