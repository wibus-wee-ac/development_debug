---
title: Session awaits
description: Let chat wait for external conditions such as GitHub CI or reviews.
---

Session await 用于把 agent run 暂停在外部条件上，例如等待 GitHub CI 或 GitHub review 状态变化。

## 先认识这个功能

当 session 正在等待外部条件时，Chat 会显示 await banner 或 await panel。用户可以查看等待来源、当前状态和摘要信息。

## 使用场景

- 等待 GitHub CI 完成。
- 等待 GitHub review 反馈。
- 等待人工手动触发。
- 在外部条件满足后恢复后续工作。

## CLI 用法

Agent 应优先使用 task-shaped CLI 命令注册 await：

```bash
cradle session await github-ci owner/repo --pr 42 --reason "Waiting for CI on PR #42"
cradle session await github-ci owner/repo --sha abc123def --reason "Waiting for CI on commit abc123def"
cradle session await github-ci owner/repo --run-id 1234567890 --reason "Waiting for one check run"
cradle session await github-review owner/repo --pr 42 --mode approved --reason "Waiting for approval"
cradle session await manual --reason "Waiting for deploy approval"
```

底层 generated command 仍保留为 escape hatch：`cradle session await-create` 可以直接传 `source` 与 `filterJson`。

## 配置前提

GitHub token、repo 权限和 private repo 访问需要在当前环境里配置好。不同组织的权限模型不同，先从能被 Cradle 读取的仓库开始验证。

## 遇到问题时

- CI 状态不更新：检查 GitHub token 和 repo 权限。
- 粘贴 GitHub Actions run URL 后不能创建 await：当前支持 PR number、commit/ref 和 check run URL，不支持 workflow run URL。
- Review 状态为空：确认目标 pull request 可访问。
- Await 变成 source failure：目标 repo、commit、PR 或 review source 不可访问，通常需要重新创建 await。
- Await 变成 delivery failure：外部条件已经满足，但恢复消息没有成功进入 Chat Runtime 队列。可以运行 `cradle session await retry <awaitId>` 重试投递，不需要再次等待 CI 或 review。
- Chat 没有恢复：查看 await panel 的当前状态，并检查 run 是否已取消。
