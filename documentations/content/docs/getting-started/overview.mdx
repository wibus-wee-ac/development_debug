Cradle 把本地项目目录、agent runtime、Chat、Issue、自动化和记忆放在同一个 workspace 中。推荐从桌面端启动，因为桌面端负责本地 server、插件 runtime、窗口状态和更新状态。

## Overview

第一次使用时只需要完成四件事。每一步都可以独立验证，不需要先理解完整架构。

<Steps>
  <Step>
    启动 [Desktop app](./desktop-app.mdx)，确认本地 server 能响应健康检查。
  </Step>
  <Step>
    添加一个本地项目目录作为 [Workspace](./first-workspace.mdx)。
  </Step>
  <Step>
    在 Settings 中配置 provider 和 model，确认 provider health 正常。
  </Step>
  <Step>
    创建 [First chat](./first-chat.mdx)，让 agent 在当前 workspace 上工作。
  </Step>
</Steps>

## 启动路径

桌面端会启动本地 server，并打开 Web workspace。Web UI 负责 home tab、workspace sidebar、Chat、Kanban、Automation、Chronicle 和 Settings。

如果你只是在浏览文档，先记住三个入口：

<Tabs items={["Home", "New Chat", "Settings"]}>
  <Tab>
    `Home` 用来查看 workspace、最近会话和常用动作。它是回到项目上下文的入口。
  </Tab>
  <Tab>
    `New Chat` 用来选择 workspace、runtime、provider 和 model。它决定下一段 session 的执行环境。
  </Tab>
  <Tab>
    `Settings` 用来配置外观、providers、agents、skills、Chronicle 和 desktop updates。
  </Tab>
</Tabs>

## 配置最小环境

进入 Settings 后，先完成 provider 配置。Cradle 的 Chat、Issue agent 和 automation 都依赖可用的 runtime profile。

配置后，在 New Chat 中选择：

- workspace。
- runtime kind。
- provider。
- model。

如果当前 runtime 需要额外凭据或不支持某些能力，界面会通过 provider health、model discovery 或运行时错误暴露问题。

## 常见边界

| Boundary | What it means |
| --- | --- |
| Home placeholders | Home 中的某些 pending run 或 artifact 展示可能来自界面占位数据，不应视为完整后端能力。 |
| Git surface | Git 面板当前可文档化的能力是状态、分支、fetch 和提交图，不应假设 push、pull、commit 或 stash 已经可用。 |
| Slack bridge | Slack bridge 是独立 app，不是 Web Settings 中的内置 Slack 页面。 |
