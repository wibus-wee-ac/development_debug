---
title: Server plugin API
description: Server plugin context, scoped routes, MCP, skills, hooks, events, and storage boundaries.
---

Server plugin API 允许 plugin 添加 server-side behavior，但不接管 Cradle core modules。Plugin 会收到 scoped context，并通过 host APIs 注册 capabilities。

## 谁负责

`packages/plugin-sdk/src/server.ts` owns public context types. `apps/server/src/plugins/context.ts` and sibling host modules own runtime behavior.

## 放在哪里

- Plugin route scope：`/api/plugins/{routeSegment}`
- MCP tools：plugin-owned tool names。
- Skills：plugin-owned skill registration。
- Hooks：host-defined hook names。
- Events：host event bus with explicit event names。

Plugin routes should not mirror core routes such as `/sessions` or `/issues`. If a plugin needs core state, it should call the core owner API.

## 怎么运行

1. Host creates `ServerPluginContext`.
2. Plugin registers routes and capabilities.
3. Host mounts plugin app under scoped route segment.
4. Runtime calls plugin handlers.
5. Host records capability metadata.
6. Host deactivates capabilities on plugin unload.

## 最小写法

```ts
import type { ServerPlugin } from '@cradle/plugin-sdk'

export const plugin: ServerPlugin = {
  activate: async (context) => {
    context.app.get('/health', () => ({ ok: true }))
  },
}
```

## 怎么验证

Plugin authors should test both context registration and hosted route behavior:

```bash
cd apps/server
pnpm test -- plugins
```

If the plugin package has local tests, run those as well.

## 边界

Server plugin API is not a database migration API. Plugin-owned storage must remain plugin-owned, and core writes must go through core owner routes or services.
