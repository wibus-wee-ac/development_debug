---
title: System Info plugin
description: Developer contract for the System Info plugin route, web panel, command, and data shape.
---

System Info 是 first-party plugin 示例。它最小化展示 server route 与 web surface 的组合方式：server layer 提供 `/info` route，web layer 注册 panel 和 command。

## 谁负责

`plugins/system-info` owns the route handler, data shape, web panel, command, and plugin-local storage key. Cradle plugin host owns route mounting, web bundle serving, and layer state.

## 放在哪里

| Surface | Identifier |
| --- | --- |
| Server route | `GET /api/plugins/system-info/info` |
| Web panel | `system-info-panel` |
| Web command | `system-info.show` |
| Storage key | `lastCheck` |

The plugin does not own Cradle core data. It reads host OS information and exposes it through plugin-owned route and UI surfaces.

## 数据形状

The route returns:

```ts
interface SystemInfo {
  hostname: string
  platform: string
  arch: string
  osType: string
  osVersion: string
  osRelease: string
  cpuModel: string
  cpuCores: number
  totalMemoryGB: number
  freeMemoryGB: number
  usedMemoryGB: number
  memoryUsagePercent: number
  uptimeHours: number
  nodeVersion: string
  homeDir: string
  pid: number
}
```

## Server 侧流程

1. Host activates server layer.
2. Plugin receives `ServerPluginContext`.
3. Plugin registers `GET /info` on the scoped app.
4. Host mounts it under `/api/plugins/system-info/info`.

## Web 侧流程

1. Host activates web layer.
2. Plugin registers `system-info-panel`.
3. Plugin registers `system-info.show`.
4. Panel fetches server route when active.
5. Command fetches server route, logs result, and writes `lastCheck`.

## 怎么验证

Manual validation:

1. Start plugin host.
2. Open Devtools Plugins.
3. Confirm server and web layers are active.
4. Fetch `GET /api/plugins/system-info/info`.
5. Open the System Info panel.
6. Run `system-info.show`.

If adding tests later, assert that the server route returns the documented fields and that web registration uses stable IDs.

## 边界

This plugin is a compact SDK example. It is not a metrics collector, alerting system, or durable inventory database. It exposes host details such as `hostname`, `homeDir`, and `pid`; treat those fields as local diagnostics.
