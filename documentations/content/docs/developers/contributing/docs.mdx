文档是契约的一部分。文档改动应说明 owner、namespace、lifecycle、interfaces、validation 和 Boundaries，而不是只描述 UI label。

## 谁负责

`documentations/content/docs/**` owns published documentation content. Each product or developer page should still defer semantics to the feature owner. Docs should not invent behavior that the code or owner has not made stable.

## 放在哪里

- Content root：`documentations/content/docs`
- Developer docs：`documentations/content/docs/developers`
- Section ordering：`meta.json`
- Page format：`.mdx`
- Frontmatter keys：`title`, `description`, `full`

Use English slugs and English identifiers. Chinese prose is expected outside code blocks, commands, paths, identifiers and frontmatter keys.

## Sidebar 结构

Every multi-page folder should include `meta.json`:

```json
{
  "title": "Developers",
  "icon": "Code",
  "pages": [
    "overview",
    "server"
  ]
}
```

Keep `pages` complete and ordered. Missing entries can lead to unstable sidebar ordering.

## 页面结构

Each page should start with direct context, then concise sections:

- `Owner`
- `Namespace`
- `Lifecycle`
- `Interfaces`
- `Validation`
- `Boundaries`

Do not turn uncertain items into release claims. Mark them as Boundaries or open questions.

## 怎么验证

```bash
cd documentations
pnpm types:check
pnpm build
```

For local review:

```bash
cd documentations
pnpm dev
```

Then inspect `/docs`, `/llms.txt`, `/llms-full.txt` and a representative `.md` route.

## 边界

Do not edit app/lib config from a content-only documentation task. If Fumadocs config or search language needs a change, handle it as a separate scoped implementation with owner approval.
