Cradle 是本地优先的 agent workspace。你可以从桌面端启动本地服务，在 Web workspace 中组织项目、会话、Issue、自动化、记忆和集成。

## Overview

Cradle 的文档按读者目标组织，而不是按仓库目录组织。先看系统地图，再进入具体任务页。

## 常用入口

<Tabs items={["User", "Admin", "Developer", "Operator"]}>
  <Tab>
    <Steps>
      <Step>
        打开 [Desktop app](./getting-started/desktop-app.mdx)，确认本地 server 已启动。
      </Step>
      <Step>
        创建 [第一个工作区](./getting-started/first-workspace.mdx)，把项目目录交给 Cradle 管理。
      </Step>
      <Step>
        进入 [Composer](./chat/composer.mdx)，选择 workspace、runtime、provider 和 model。
      </Step>
    </Steps>
  </Tab>
  <Tab>
    <Steps>
      <Step>
        在 [Providers](./agents/providers.mdx) 配置模型提供商，并检查 provider health。
      </Step>
      <Step>
        阅读 [Approvals](./chat/approvals.mdx)，确认哪些 agent 操作需要人工确认。
      </Step>
      <Step>
        用 [Settings](./operations/settings.mdx) 管理外观、desktop updates、skills 和 Chronicle。
      </Step>
    </Steps>
  </Tab>
  <Tab>
    <Steps>
      <Step>
        从 [Developer overview](./developers/overview.mdx) 理解 owner、namespace 和 lifecycle。
      </Step>
      <Step>
        阅读 [OpenAPI](./developers/api/openapi.mdx) 与 [Generated CLI](./developers/cli/generated-cli.mdx)，确认 route 到 command 的契约。
      </Step>
      <Step>
        进入 [Plugin SDK](./developers/plugins/sdk-overview.mdx)，按 layer 和 capability 扩展 Cradle。
      </Step>
    </Steps>
  </Tab>
  <Tab>
    <Steps>
      <Step>
        打开 [Devtools](./operations/devtools.mdx)，查看 Server Health、Observability 和 plugin state。
      </Step>
      <Step>
        阅读 [Chronicle](./chronicle/overview.mdx) 与 [Slack bridge](./integrations/slack-bridge.mdx)，理解跨进程和外部 bridge。
      </Step>
      <Step>
        从 [Troubleshooting](./troubleshooting/index.mdx) 进入具体故障页，并在删除本地状态前导出证据。
      </Step>
    </Steps>
  </Tab>
</Tabs>

## 管理与排障

Cradle 的复杂能力通常跨越 Web UI、本地 server、桌面 runtime 和插件层。遇到问题时，优先从 [故障处理入口](./troubleshooting/index.mdx) 开始，再进入具体页面。

<Callout type="info">
文档只描述当前仓库证据支持的行为。未确认的发布渠道、云同步能力、未来 UI 和外部托管能力不会作为已发布功能描述。
</Callout>
