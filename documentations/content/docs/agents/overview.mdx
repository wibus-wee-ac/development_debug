Agents 是 Cradle 执行任务的运行单元。它们通过 runtime kind 连接 provider、model、tools、skills 和 workspace context。

## 先认识这个功能

管理员通常先配置 providers 和 models，再决定 runtime kind 与 agent identity。普通用户在 New Chat 或 Issue detail 中选择可用 agent。

## 推荐顺序

<Steps>
  <Step>
    配置 [Provider](./providers.mdx)，确认 credential 和 provider health。
  </Step>
  <Step>
    刷新或搜索 [Model](./models.mdx)，确认目标模型在当前 runtime 中可见。
  </Step>
  <Step>
    选择 [Runtime kind](./runtime-kinds.mdx)，明确 task 会在哪类 adapter 中执行。
  </Step>
  <Step>
    按任务进入 Chat、Issue agent 或 Automation。
  </Step>
</Steps>

## 使用路径

<Tabs items={["Chat", "Issue agent", "Automation"]}>
  <Tab>
    Chat 以当前 workspace 和 session 为中心。用户选择 runtime/provider/model 后，agent 读取上下文、请求 approval，并把结果写回 session timeline。
  </Tab>
  <Tab>
    Issue agent 以 issue owner 为中心。它需要可委派的 agent identity，执行记录应回到 issue activity 和 session 关联关系。
  </Tab>
  <Tab>
    Automation 以 durable run 为中心。它需要明确 trigger、artifact、run status 和失败重试边界。
  </Tab>
</Tabs>

## 使用前先知道

不是所有 agent identity 都能被委派给 Issue agent。遇到 `issue_agent_agent_not_supported` 这类错误时，换用 provider-backed agent。
