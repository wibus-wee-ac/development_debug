# Components/Layout

Core layout primitives for the application shell.
These components define the spatial structure (sidebar, center, aside, panel).
Place domain-specific content components in `features/` instead.

## Files

- **app-footer.tsx**: Slim footer bar mirroring the AppHeader chrome pattern; Jarvis session tabs use sibling native buttons for activation and close actions without nested interactive controls, and pass the active tab ref to the Jarvis popover so anchor measurement does not require footer state updates during resize; the Ask Jarvis entry exposes a stable E2E anchor for keyboard-activated popover coverage.
- **app-footer.test.tsx**: Regression tests for AppFooter Jarvis session activation and close button semantics.
- **app-header.tsx**: Slim top chrome with tab capsule bar, Settings-mode active tab presentation, workspace/title/git breadcrumb slot rendering, and browser/bottom-panel/right-aside toggles driven by active layout slot capabilities; chat tabs project session-activity unread state into the tab badge slot while preserving Meta-key number hints as the higher-priority leading-slot overlay; the BrowserPanel toggle reads and writes the active Cradle tab's owner-scoped browser panel visibility; layout state subscriptions are scoped to fields the header renders so resize-only updates do not repaint the tab chrome; interactive regions are marked `no-drag`, key toggles expose accessible names / pressed states, Settings mode hides panel toggles without changing their stored open state, tear-off windows reserve macOS traffic-light space while hiding the main-window sidebar control, session-scoped windows suppress new-tab and nested tear-off actions, successful chat tear-off opens reserve the session across pointer-monitor/release entry points before detaching the chat tab from the main tab bar until the tear-off closes, resources diagnostics, browser panel, and bottom-panel terminal code are preloaded from header intent, the browser panel, chat Files aside, and bottom-panel shell open intents record first-render performance start marks, and stable `data-testid` anchors remain available for E2E
- **app-header.test.tsx**: Regression tests for AppHeader toggle accessible names, pressed states, callback wiring, and browser/bottom-panel shell performance intent marking.
- **app-layout.tsx**: Pure three-column layout shell — sidebar (via AppSidebar), center column (header/main/footer/panel), and aside. Reads dynamic layout slots from `LayoutSlotsContext` so active tab content can inject aside/panel/title/browser capabilities without prop drilling, projects the active Cradle tab id into BrowserPanel owner state, lets tear-off windows opt out of the main-window footer/Jarvis surface and mark tab chrome as session-scoped, keeps the Electron Browser Panel mounted at the layout boundary and switches owner-scoped visibility through React Activity, installs the Electron browser-use bridge for owner-scoped browser panel tab creation/activation/offscreen hiding with active chat source metadata, collapses the owner-scoped BrowserPanel when its final inner tab closes, owns the Meta+. Zen shortcut that expands both available sidebars or collapses them when already expanded, subscribes to layout store fields through scoped selectors so unrelated store writes do not repaint the whole shell, applies browser/bottom/aside size changes as immediate layout values rather than `motion` layout animations, reads browser panel drag width from a DOM ref instead of resize-driven React state, keeps Settings mode from rendering browser/bottom/right surfaces while preserving their stored open state, keeps closed right-aside content unmounted so deferred panels do not run hidden work, and exposes stable `data-testid` + open-state anchors for E2E shortcut assertions. Settings content is supplied by the app shell as a tab-canvas overlay rather than owned by the layout itself.
- **app-sidebar.tsx**: Workspace sidebar wrapper with settings navigation button. Handles keyboard shortcuts for toggling settings route and sidebar collapse, preloads settings content before opening the overlay, keeps sidebar content behind a memoized render boundary during width drags, commits persisted layout width once at pointer-up, applies collapsed width directly rather than animating layout width, and exposes stable sidebar mode / collapsed-state anchors for E2E assertions.
  Extracted from AppLayout to keep layout concerns separate from sidebar orchestration.
- **dev-bottom-bar.tsx**: Dev-only slim footer inside `AppLayout` that subscribes to the active tab route projection and exposes DevTools / hard reload actions
- **layout-geometry-context.tsx**: Explicit layout geometry contract that registers the center column and footer elements through stable callbacks, letting overlays measure DOM nodes only while active without broadcasting resize-driven rect state through React context
- **layout-contract.ts**: Route-first layout chrome contract that derives right-aside, browser panel, and bottom panel identity synchronously from the active tab plus cached session/workspace metadata, including CLI-TUI workspace chats, while only accepting matching active-tab slots for panel content.
- **layout-contract.test.ts**: Regression tests for ignoring stale tab slots during sidebar tab replacement and preserving CLI-TUI layout capability semantics.
- **layout-slots-context.tsx**: React context + `LayoutSlotsProvider` for per-tab layout slot injection (asideSessionId, asideWorkspaceId, panel, hasAside, hasPanel, hasBrowserPanel, title, workspace, gitBranch). Consumed by `AppLayout` and used by tab content components via `useRegisterLayoutSlots`; the provider accepts active/valid tab slot ids, prunes slots for closed tabs, and retains the last known slot value while a newly active retained frame has not registered its slots yet.
- **layout-slots-context.test.tsx**: Regression tests for stable layout slot output when switching to a tab whose retained frame has not registered its slots yet.
- **resize-handle.tsx**: Draggable handle for resizing sidebar, aside, and panel widths/heights; accepts eager numeric bounds or lazy readers for DOM-measured drag constraints and can separate high-frequency drag updates from the final committed value.
- **right-aside.tsx**: Tabbed right side panel with File Tree, Changes, Git, Issue, Runtime, and Feed tabs; accepts either a chat session or workspace id, derives workspace details and session runtime metadata as needed, renders Git working-tree changes through the Git-owned Changes panel with workspace path and Pack handoff wiring, renders chat runtime progress/status through the Chat-owned runtime panel, auto-sizes active tab labels from translated text, can launch the pack-codebase dialog from file tree flows, and exposes stable tab/content `data-testid` anchors for E2E navigation
- **use-layout-slots.ts**: `useLayoutSlotsCtx` and `useRegisterLayoutSlots` hooks for reading and registering layout slots from tab content components; retained tab frames keep slot registration effects mounted while inactive, so this hook registers slots without unregistering on effect cleanup and lets `LayoutSlotsProvider` prune by valid tab ids.
