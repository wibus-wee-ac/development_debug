# Features/Chat

Renderer-side view layer for chat.
Streaming updates arrive as AI SDK `UIMessageChunk` frames through a chat-owned transport abstraction. Ordinary web runtime uses server SSE directly. Electron Desktop runtime uses `window.cradle.chatStream`, where Electron main owns the long-lived upstream server SSE connection and renderer windows consume IPC fanout. Initial hydration and reload/recovery read trusted `UIMessage` snapshots through React Query and project locally into Zustand.
Passive windows hydrate the current message snapshot first, then subscribe through `chat-stream-transport.ts` for active-run AI SDK chunks instead of polling snapshots while a message is streaming. In web runtime this transport calls `GET /chat/sessions/{sessionId}/stream`; in Electron Desktop it subscribes to the main-process broker so multiple windows share one upstream stream. The passive chunk consumer always rebuilds the active assistant message from the replayed stream protocol instead of using the hydrated snapshot as AI SDK internal stream state, so late joins receive required part-start chunks before text/reasoning deltas even when the DB snapshot is still empty during streaming.
Text/reasoning/file parts hydrate as `UIMessage.parts`. Tool calls are normalized into browser-owned tool entities keyed by `toolCallId` after AI SDK projection has produced full message snapshots; this keeps rendering state local without reintroducing Cradle-owned part-delta reducers.
The store preserves raw AI SDK `UIMessage.parts` as the message-history source of truth. Tool entities are render indexes only; they must not rewrite tool parts because native AI SDK approval continuation depends on fields such as `approval`, `input`, `providerExecuted`, and output state staying inside the `UIMessage`.
Native AI SDK tool approvals render inline from tool parts with `state: "approval-requested"`. Approve/deny actions update the tool part to `approval-responded`, use AI SDK `lastAssistantMessageIsCompleteWithApprovalResponses`, and continue by sending the complete `messages` history through the existing chat response endpoint. They do not use the deleted independent approval stream.
Claude Agent `TodoWrite` state is synthesized by the server adapter into persisted tool output `pluginState.todos`. Chat store selectors reverse-scan raw `UIMessage.parts` for the latest plugin state and render it in Composer-adjacent progress and Right Aside runtime surfaces; inline `TodoWrite` blocks may still project directly from tool args while the call is running. The TODO shared vocabulary is `todo` / `processing` / `completed`, with processing text read from `activeForm`. Codex app-server plan/file/MCP/web tool items render through the same classified tool block surface. Claude Agent only exposes `bypassPermissions` and `plan` mode through Chat Runtime's permission-mode endpoint and a compact Composer segmented control; idle changes are sent with the next run, and streaming changes also call the active runtime side-channel.
Subagent progress renders from parent tool outputs. Claude Agent subagent chunks arrive as preliminary AI SDK `tool-output-available` data containing `{ type: "cradle.subagent-output.v1", message }`; nested activity is read from that tool output instead of a client `parentToolCallId` routing map.
When a session is already streaming, the composer can submit a durable Chat Session
continuation item instead of starting a second run. The default mode comes from Chat
settings, `Shift+Meta+Enter` flips between `queue` and `steer` for one send, and the
visible queue controls cancel, drag/drop reorder, or button-reorder pending items through
chat-runtime endpoints.
AI SDK wire validation is intentionally limited to the SSE boundary through `uiMessageChunkSchema`. Once a frame has been accepted as an AI SDK chunk or a snapshot has been loaded from Cradle's own database, chat feature code treats the object as trusted and uses direct TypeScript narrowing instead of feature-owned Zod schemas.

## Files

- **chat-tool-entities.ts**: Browser-owned tool entity normalization and tool-anchor helpers used by hydration, AI SDK snapshot replacement, and message rendering
- **chat-capabilities.ts**: Feature-owned GET boundary for `/chat/sessions/{sessionId}/capabilities`, used only for runtime-native capability data such as provider slash commands. The response is a Cradle-owned trusted API payload.
- **chat-context.ts**: Chat-owned Jarvis semantic context provider; publishes active chat attention state such as viewport range, scroll position bucket, near-bottom/manual-scroll state, and composer focus without exposing Chat DOM structure to system-agent
- **chat-context.test.ts**: Unit coverage for Chat attention snapshot publication into typed Jarvis context envelopes
- **chat-slash-commands.ts**: Web-owned slash command descriptor and merge helpers; converts runtime-native commands into raw text insertion actions, supplies fallback runtime command descriptors for pre-session composer surfaces, registers Cradle UI commands such as `/appshot`, and keeps Cradle UI commands separate from provider capabilities
- **chat-response-command.ts**: Feature-owned HTTP command boundary for `/chat/sessions/{sessionId}/response`, `/chat/sessions/{sessionId}/stream`, `/chat/sessions/{sessionId}/cancel`, `/chat/sessions/{sessionId}/permission-mode`, and `/chat/sessions/{sessionId}/queue`; long-lived response/stream calls are now consumed through `chat-stream-transport.ts` so Electron can replace renderer-owned SSE with desktop IPC fanout while web runtime keeps the same HTTP path.
- **chat-stream-transport.ts**: Chat-owned transport abstraction for starting response streams and joining active session streams. It chooses Electron main-process IPC when `window.cradle.chatStream` is available, buffers early IPC events until the renderer stream is attached, validates incoming chunks with AI SDK `uiMessageChunkSchema`, and falls back to the existing HTTP SSE parser outside Electron.
- **chat-stream-transport.test.ts**: Regression coverage for Electron event-backed stream creation, Electron error propagation, and HTTP SSE fallback behavior.
- **chat-continuation-metadata.ts**: Chat-owned reader and optimistic message factory for `metadata.cradle.continuation`, keeping queue/steer presentation metadata separate from provider-visible message parts.
- **chat-queue-list.tsx**: Shared compact continuation queue list with mode badges, drag/drop reorder, up/down button reorder, and pending-item cancellation controls.
- **chat-runtime-view.tsx**: Chat session runtime boundary shared by normal tab routes and the dedicated Electron tear-off renderer, passing runtime ownership into chat rendering while keeping chat rendering independent from the main app shell and tab registry.
- **chat-todo-projection.ts**: Chat-owned TODO plugin-state reader and inline TodoWrite projection model; session surfaces read persisted `pluginState.todos`, while tool blocks can map live tool args into the same `todo` / `processing` / `completed` vocabulary.
- **use-session-todos.ts**: Session-level selector hook that scans persisted `UIMessage.parts` from newest to oldest and exposes the latest adapter-synthesized TODO snapshot for Right Aside and Composer-adjacent surfaces.
- **runtime-session-status-command.ts**: Chat-owned HTTP reader for server-owned `/chat/sessions/{sessionId}/runtime-status` data used by runtime status surfaces.
- **use-runtime-session-status.ts**: React Query hook for server-owned runtime session status with light polling while a run is active, pending, or cancelling.
- **runtime-session-panel.tsx**: Right Aside runtime status panel for the selected chat session; summarizes server-owned runtime status, UI-visible status, runtime/provider/session identity, latest run timing, queue counts, and recent tool-call state from chat store indexes.
- **permission-mode-control.tsx**: Compact Composer Plan/Bypass segmented control for Claude Agent permission mode, shared by idle and streaming chat states.
- **chat-view-loader.ts**: Shared loader and route preload entry for the Chat tab, reused by session links, search results, and tray actions.
- **appshot-attachment-model.ts**: Cradle-owned AppShot `FileUIPart` metadata helpers; creates and reads `providerMetadata.cradle.appshot` while keeping model input compatible with normal image file parts.
- **appshot-attachment.tsx**: Cradle-owned AppShot composer/thread visual card; composer rendering keeps only the Codex-sized transition snapshot slot as the native transition target, and thread rendering uses the final capture image with Codex-like centered image, mask, shadow, sibling icon overlay, and caption treatment.
- **use-chat-session.ts**: Chat session hook — uses React Query for canonical snapshot rows and queue items, hydrates AI SDK `UIMessage` snapshots, passively restores currently streaming assistant message ids for reload recovery, joins the active session AI SDK chunk stream after hydration, restores only the latest failed main assistant row as the current session error, drives streaming responses with text plus `FileUIPart[]`, handles AI SDK native approval response by updating the latest assistant tool part to `approval-responded` and resubmitting complete `messages` history, enqueues follow-up continuations while busy, projects completed live steer items into the visible message list before canonical snapshot sync, locally releases stop state immediately, forwards compatible active-run permission mode switches, refreshes snapshots after server-owned cancellation settles, and exposes low-frequency session controls plus `{ messageIds, messageCount, status, error }` so message text streaming stays at the message subscription boundary.
- **use-session-await.ts**: Session await summary hook used by the chat view to reflect pending await state with the shared interactive query refresh policy.
- **sse-chat-transport.ts**: Thin web/runtime HTTP SSE parser using `parseJsonEventStream` and `uiMessageChunkSchema`; also emits lightweight run activity notifications for app chrome.
- **chat-view.tsx**: Read-only chat view — reads low-frequency session state from useChatSession, renders MessageBubbles by per-message store subscriptions + Composer, shows pending Chat Session queue items, adapter-synthesized TODO progress, and compatible Plan/Bypass controls near the Composer, accepts workspace file drops into the composer, consumes scroll/composer/Appshot runtimes for virtua, minimap, attention snapshots, send actions, slash commands, token usage, attachment capability, and desktop capture, and records the global Chat first-render performance measure once per module lifetime.
- **use-chat-scroll-runtime.ts**: Chat-owned scroll controller hook for ScrollArea and virtua refs, streaming keep-mounted indices, near-bottom auto-scroll, minimap progress writes, click/drag scroll actions, and Jarvis attention viewport snapshots.
- **use-chat-composer-runtime.ts**: Chat-owned composer integration runtime for session binding, runtime slash capabilities, fallback Cradle commands, model attachment capability, token usage, continuation-mode send actions, and stop state.
- **use-composer-appshot-capture.ts**: Composer-owned desktop Appshot capture runtime; keeps native hotkey subscription stable through refs, owns pending Appshot slots, measures action targets, and injects captured file parts into Composer without leaving capture orchestration in ChatView.
- **chat-share-export.tsx**: Chat-owned share dialog that renders an off-scroll Cradle-styled conversation surface, lets users export the full session or selected messages, and uses `modern-screenshot` to download or copy a PNG without depending on the virtualized message list.
