# Codex Runtime Provider

Owns the Codex app-server runtime adapter for Chat Runtime. This directory translates between Cradle `UIMessage` state and the Codex JSON-RPC app-server protocol.
Codex tool identity and the `{ identifier, apiName, args, result }` envelope are owned by `tools/`; this provider only maps app-server protocol items into that stable contract.
Selected chat Skills arrive as Cradle-owned `data-cradle-skill` message parts. The provider reads them and projects them into Codex app-server `UserInput` skill items without writing to any skills namespace.
Codex thread display titles are read from app-server `thread/start`/`thread/resume` responses, `thread/name/updated` notifications, and final `thread/read` metadata, then reported through Chat Runtime's title callback. Provider metadata is normalized as `name`, then persisted `title`, then `preview`; Cradle owns the final `sessions.title` write. When a fresh Codex thread starts without a name, this provider opportunistically starts a separate ephemeral app-server title thread in the background, using Chat-owned title-generation preferences for provider target, explicit model, and thinking effort; when provider/model are unset it follows the active chat session provider/model. The generated title is written back through app-server `thread/name/set` for the main thread and reported to Chat Runtime; the title turn is not awaited by the main `turn/start` path and is not injected into the main Codex session.
Codex app-server child processes receive Cradle-owned `CRADLE_CHAT_SESSION_ID`, `CRADLE_WORKSPACE_ID`, `CRADLE_WORKSPACE_PATH`, and agent context env vars when available so tools and shell subprocesses can call back into Cradle with the current chat/workspace/agent context. These values are convenience context only; authoritative ownership still comes from Chat Runtime resolving `sessions.workspaceId` and `sessions.agentId`.
Agent-scoped Codex sessions use `~/.cradle/agents/{agentId}` as app-server `cwd`. The original project remains explicit through `runtimeWorkspaceRoots`, sandbox writable roots, and `CRADLE_WORKSPACE_PATH`; the provider does not change Codex's global `CODEX_HOME`, which stays under Cradle's app-server runtime data directory.
Official Codex/ChatGPT auth is owned by Cradle credentials. Model Providers lets each manual provider create or bind its own ChatGPT credential; the login runs the ChatGPT device auth flow from Cradle and stores token material as an encrypted JSON `chatgpt-auth` secret. The provider passes the selected provider target's credential to app-server through `account/login/start` with `chatgptAuthTokens`, leaves API key environment variables unset, and handles app-server `account/chatgptAuthTokens/refresh` requests by refreshing the OAuth token and writing the updated JSON back to that same Cradle encrypted secret. OpenAI-compatible `baseUrl` targets still require API key credentials and are projected as explicit Codex model providers.
Existing Codex threads are resumed with `excludeTurns: true`, then immediately read through `thread/turns/list` using `itemsView: "full"` and ascending pagination. Cradle stores that best-effort full app-server turn page in the provider snapshot under the Codex namespace it owns; this captures everything app-server can reconstruct from persisted Codex rollout history without writing duplicate native history back into Codex. When a later provider-target change forces a fresh Codex thread, Cradle carries the previous Codex native history snapshot through `StartChatSessionInput.previousProviderStateSnapshot`, projects it to Responses API items, and injects it before the first turn so the new thread receives the richest app-server history Cradle had already fetched.
Goal slash commands and internal goal continuations are provider-native control messages, not chat text. A visible `/goal <objective>` command or goal metadata message sets `thread/goal/set` with an objective, and an internal Chat Runtime goal-continuation message sets `thread/goal/set` with `status: "active"` without calling `turn/start`. The provider then streams the resulting app-server notifications as the current run. User cancellation pauses an active Codex goal in the provider snapshot before interrupting the current turn so Chat Runtime does not auto-resume from stale active-goal state.
Composer bang commands in Codex runtime are provider-native shell commands, not Chat Runtime local execution. Chat Runtime calls the provider's `executeShellCommand` hook, and the provider resumes/starts the Codex thread, sends `thread/shellCommand`, waits for the matching `commandExecution` item, hydrates native history, and returns bounded result metadata for Cradle's UI snapshots.
Side chat remains Cradle-owned and live-only. When Chat Runtime asks for `forkRuntimeSession`, this provider maps the parent Codex thread to app-server `thread/fork` with an ephemeral, turn-excluding child thread, injects a Cradle side-boundary prompt through `thread/inject_items`, and returns the forked provider thread id for the process-local side runtime session. The provider does not create a durable binding for the child; `ProviderRuntimeHostManager` keeps the app-server client alive through the pinned side host lease while the side session is live. Providers that do not expose this hook still receive Chat Runtime's Cradle transcript fallback; Codex's hook only upgrades native fidelity.
Codex app-server stream failures keep user-facing errors short: retry-limit and status failures are summarized through `CodexProviderError.data.details`, while full raw event samples, counts, and app-server error notifications stay in `data.diagnostics` for observability/debugging.
Codex token usage notifications stay provider-owned at the protocol boundary: `thread/tokenUsage/updated` is projected into Codex UI slot state and the provider's `lastUsage` / `lastModelId` read model. Chat Runtime owns the durable `usage_logs` write during run finalization.
Codex UI slots are projected from the app-server capability manifest and declare their intended Cradle surfaces. Slot state stays provider-owned: `goal` reads `thread/goal/get` and can render in composer state plus slash/runtime surfaces; `compact` starts from the provider-native `thread/compact/start` request instead of a raw `turn/start` slash message, keeps lifecycle from `contextCompaction` item `item/started` and `item/completed`, treats deprecated `thread/compacted` only as a compatibility signal, and keeps the usage meter from thread-level `thread/tokenUsage/updated` plus effective config limits such as `model_auto_compact_token_limit`; `status`, `model`, and `reasoning` come from thread start/resume responses, settings/status notifications, config, model list, and model-provider capability reads; `plan` uses `turn/plan/updated` as the canonical session plan snapshot; `toolActivity` summarizes recent `item/started` and `item/completed` lifecycle records; `mcp` merges `mcpServerStatus/list` reads with startup, OAuth, and progress notifications; `diff`, `terminal`, `approvals`, and `alerts` summarize their corresponding app-server notifications without storing full output history, with `alerts` exposed only as runtime-panel snapshot state; `filesystem` and `search` keep bounded notification snapshots from `fs/changed` and fuzzy file search; `usage` reads `account/rateLimits/read`, listens to rate-limit updates, and exposes ChatGPT account usage on slash-command and runtime-panel surfaces with the original primary/secondary window duration and reset timestamps; `skills`, `plugin`, `crew`, and `config` are read from app-server list/read methods at render time. `crew` enumerates Codex-owned subagent threads through paginated app-server `thread/list`, keeps recent collab tool-call lifecycle only as call/activity summary state, and resolves thread metadata so Runtime surfaces can show subagent nickname, role, title, preview, and model provider without depending on a bounded parent-turn window. Cradle stores only the provider snapshot needed to replay those projections across composer state, slash command rows, toolbar option summaries, Right Aside Runtime cards, and stream evidence blocks.

## Files

- `provider.ts`: Codex `ChatRuntime` facade; acquires session-scoped app-server clients through `ProviderRuntimeHostManager`, starts/resumes app-server threads, forks ephemeral provider-native side threads for Chat Runtime side sessions, fetches full app-server turn history for resumed native threads, reports app-server thread display titles, generates missing titles through a background ephemeral Codex title thread, injects reconstructed Cradle history and side boundaries through `thread/inject_items`, starts normal turns, executes user shell commands through `thread/shellCommand`, exposes provider-native app-server capabilities/invoke/stream hooks through Chat Runtime, projects goal invoke results into the provider snapshot, activates provider-native goal continuations, streams notifications, and handles live steering/cancellation.
- `provider.test.ts`: Regression tests for Codex thread startup, provider title projection, provider config, transcript reconstruction, UI slot state projection, streaming, steering, cancellation, and diagnostics.
- `metadata.ts`: Codex runtime kind, catalog metadata, static capabilities, and app-server capability presentation projection.
- `types.ts`: Codex provider-private client, dependency, and active-turn types shared by package modules.
- `input-projector.ts`: Projects Cradle `UIMessage` text/file/skill input and Codex-native `/goal` and `/compact` control messages into app-server input semantics.
- `state-projector.ts`: Projects Codex app-server notifications, thread reads, and provider-native invoke results into Cradle-owned provider snapshot state, including goal, status/model/reasoning, compact, plan, tool activity, MCP, diff, terminal, approvals, alerts, filesystem/search/usage, and restorable native history captured from app-server turn reads.
- `stream-handler.ts`: Owns Codex turn notification iteration, active-goal continuation delay, and provider-thread live event fanout.
- `stream-diagnostics.ts`: Owns Codex stream diagnostics, bounded event samples, short failure summaries, title normalization, and provider error payloads.
- `app-server-client.ts`: Newline-delimited JSON-RPC client for Codex app-server processes; declares Cradle client identity and version during app-server initialization.
- `app-server-client.test.ts`: Client path, transport, and initialization identity tests.
- `chatgpt-auth.ts`: Parses Cradle-owned ChatGPT auth secrets, builds Codex external auth login params, refreshes OpenAI OAuth access tokens, and persists refreshed token material back to the encrypted secret store.
- `event-to-chunk-mapper.ts`: Maps Codex app-server notifications into AI SDK `UIMessageChunk` events carrying Cradle-owned tool envelopes. Reasoning items are projected only when Codex provides displayable `content`, `summary`, or reasoning deltas; encrypted-only reasoning is not surfaced as an empty UI part.
- `app-server-capabilities.ts`: Generated Cradle-owned manifest of the app-server client methods, server requests, and server notifications.
- `app-server-host-resource.ts`: Provider-private shared app-server host resource helper used by normal turns, side turns, UI-slot reads, and provider-native app-server bridge calls so they share the same session-scoped `ProviderRuntimeHostManager` resource, request handler dispatch, and notification subscriber pump.
- `app-server-bridge.ts`: Provider-private bridge for invoking generated app-server methods and streaming raw notifications as SSE from Codex provider-native app-server hooks.
- `runtime-context.ts`: Resolves per-session Codex cwd, agent home, project workspace path, and app-server runtime workspace roots.
- `tools/`: Codex tool identifier and app-server item payload mapper.
- `native-history-projector.ts`: Projects full Codex app-server `Turn` snapshots into Responses API items for best-effort restoration when a fresh Codex thread replaces a previous native thread.
- `transcript-projector.ts`: Projects reconstructed Cradle transcript history into Codex Responses API items for native thread injection, unwrapping tool envelopes and Cradle bang-command result metadata back to provider-native function-call names, arguments, and outputs.
- `ui-slot-projector.ts`: Projects generated Codex app-server capabilities into runtime UI slot descriptors and projects provider snapshots plus app-server config/list/native reads into `RuntimeUiSlotState[]`.
- `app-server-protocol/`: Generated TypeScript bindings from `codex app-server generate-ts --experimental --out apps/server/src/modules/chat-runtime-providers/codex/app-server-protocol`. Do not edit generated files by hand.

## Regeneration

After regenerating `app-server-protocol/`, run `pnpm --filter @cradle/server generate:codex-app-server-capabilities` to refresh `app-server-capabilities.ts`. The capability generator derives method names and params from the generated protocol files, and keeps only Cradle-owned runtime semantics such as stream-capable methods in the generator.
